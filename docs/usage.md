## Что делает Niche Radar

Niche Radar превращает CSV-отчёты популярных запросов Яндекс Wordstat (сервис
Bukvarix) в проверяемые продуктовые гипотезы для онлайн-сервисов. Типичный путь:

```
CSV-отчёт Bukvarix → импорт → поиск растущих фраз → ниши → гипотезы → эксперименты
```

Приложение локальное: без аутентификации, работает на вашем компьютере через
Docker Compose и доступно на `http://localhost:8080` (порт меняется через
`APP_PORT` в `.env`). Ваши данные никуда не отправляются.

## Подготовка данных

### Где скачать отчёт

CSV-файлы для импорта скачиваются со страницы
<https://www.bukvarix.com/top-keywords/>:

- **Top-10** — небольшой отчёт-образец; он же включён в репозиторий как
  `data/Top10.csv`;
- **Top-100 … Top-3 000 000** — полные отчёты для содержательного анализа.

Скачанные файлы кладите в каталог `data/` — он исключён из git (кроме образца
`Top10.csv`), поэтому большие отчёты не попадут в репозиторий.

### Что внутри файла

Каждая строка — ключевая фраза с текущим и предыдущим рангом и **шестью замерами**
частотностей: колонки с суффиксами `6` (самый старый) … `1` (самый новый).
Для каждого замера есть две частотности:

| Частотность | Обозначение | Смысл |
|---|---|---|
| Широкая («Частотность Весь мир») | broad | Показы по фразе с любым порядком и добавленными словами |
| Точная (`"[!Частотность !Весь !мир]"`) | exact | Показы в точном написании фразы |

**Базовая метрика спроса в Niche Radar — точная частотность.** Широкая
показывается отдельно и не суммируется по фразам как «объём рынка» (они
пересекаются).

Импортёр сам распознаёт заголовки по именам (разделители `;`, `,`, TAB;
UTF-8 с BOM и без; кавычки и переносы строк в полях поддерживаются). Даты
замеров Bukvarix не публикует, поэтому история показывается как порядковые
замеры 1…6, а не как месяцы.

## Импорт отчёта

Импорт идемпотентен: повторный запуск того же файла (совпадает SHA-256) не
дублирует данные, а возвращает существующий отчёт. Одинаково доступны два
способа — через интерфейс и из терминала.

### Через интерфейс («Данные», `/data`)

1. Нажмите **«Загрузить»** и выберите CSV-файл (до 5 GiB по умолчанию).
2. Дождитесь предпросмотра: приложение определит разделитель, заголовки и
   предложит сопоставление полей. Если заголовок нераспознаваем, импорт
   перейдёт в состояние `needs_mapping` — сопоставьте колонки вручную.
3. Укажите **тип охвата** (ТЗ §4.3): «полный топ» (`full_top`), «выборка»
   (`sample`), «отфильтрованная выборка» (`filtered`) или «охват неизвестен».
   Тип выбираете вы — он не выводится из имени файла или максимального ранга.
   Для `Top10.csv` правильно: «выборка».
4. Запустите обработку кнопкой **«Запустить импорт»**. Дальше фон: валидация →
   загрузка в базу → расчёт метрик. Прогресс, скорость и время видны в карточке
   отчёта. Ошибки сохраняются с номером записи CSV, колонкой и причиной —
   получить их можно запросом `GET /api/v1/imports/{id}/errors`.
5. После перехода в статус `готово` нажмите **«Сделать активным»**, если отчёт
   должен стать рабочим.

Новый отчёт **не** подменяет активный сам: до успешной публикации и вашего
явного выбора работа продолжается со старым.

### Из терминала

```bash
./bin/import "$(pwd)/data/Top10.csv" --coverage=sample --title="Bukvarix Top-10"
./bin/import /abs/path/Top3000000.csv --coverage=full_top
```

Полезные флаги: `--coverage=…` (тип охвата), `--title=…` (название отчёта),
`--skip-invalid` (пропустить ошибочные записи — частичная публикация с отметкой
о неполноте; по умолчанию режим строгий), `--wait` (ждать завершения; включён
в `bin/import` автоматически). Логи очереди: `docker compose logs -f worker-import`.

### Статусы и восстановление

`загружен → сопоставление → в очереди → валидация → загрузка → расчёт метрик →
готово`; ошибки — `failed`, отмена — `cancelled`. Кнопки «Отменить» и
«Повторить» доступны в карточке отчёта. Повтор запускает текущий этап с начала
(без дублирования наблюдений), завершённые этапы переиспользуются.

### Контроль корректности

На образце `data/Top10.csv` после импорта должно быть (ТЗ §14.1):

- 10 фраз, 10 строк `dataset_keywords`, 6 замеров, 60 наблюдений;
- фраза «переводчик»: точная текущая частотность `21 466 358`, точная история
  `24704716, 24993362, 25094186, 24831529, 25726636, 21466358`;
- пресет «Устойчивый рост» — **0 из 10** фраз (см. [частые вопросы](#частые-вопросы)).

## Рабочий цикл исследования

1. **Импортируйте** отчёт и сделайте его активным.
2. **Дашборд** (`/dashboard`) — обзор активного отчёта: число фраз, лидеры
   роста/падения, новые участники рейтинга, предупреждения качества.
3. **Исследование** (`/explore`) — основной экран: фильтры и пресеты, отбор
   фраз. Состояние фильтров хранится в URL — ссылкой можно поделиться или
   сохранить как именованный поиск.
4. **Карточка фразы** (`/keywords/:id`) — история, графики, компоненты
   приоритета, похожие фразы.
5. **Кандидаты** (`/candidates`) — готовые подборки: растущие фразы по пресетам
   и автоматические предложения групп по повторяющимся словам.
6. **Ниши** (`/niches`) — сохранённые подборки фраз с версиями состава; метрики
   ниши и сравнение двух отчётов.
7. **Гипотезы** (`/hypotheses`) — карточки продуктовых гипотез с фиксацией
   следующего эксперимента и статуса.

Экспорт выборки — кнопка «Экспорт CSV (вся выборка)» на экране «Исследование».
Экспорт выполняется фоновой задачей: приложение покажет идентификатор задания;
статус и готовый файл — через REST (`GET /api/v1/exports/{id}` и
`GET /api/v1/exports/{id}/download`). Экспортируется вся выборка по фильтрам,
а не текущая страница; формат — UTF-8 с BOM, разделитель `;`. Карточку гипотезы
можно выгрузить в Markdown (кнопка «Экспорт Markdown»).

## Экраны приложения

### Исследование (`/explore`)

Серверная таблица фраз с фильтрами (ТЗ §5.2):

- отчёт и диапазон замеров;
- фраза: точная фраза / подстрока / включающие и исключающие слова
  (режимы: любое из слов или все слова; совпадение целым токеном или подстрокой);
- частотности (точная/широкая), число слов, абсолютный и относительный рост —
  диапазоны «от/до»;
- устойчивость, сохранение относительно пика, число замеров;
- флаги: впервые в рейтинге, низкая база, неполная история, признаки
  программной задачи / информационного / навигационного запроса;
- свои метки, принадлежность нише, словарь брендов.

Сортировка серверная, по 50 строк на страницу (до 200). Действия над строками:
открыть карточку фразы, добавить выбранные фразы в нишу, сохранить поиск,
экспортировать выборку. Загрузить все 3 млн строк в браузер нельзя —
используйте фильтры и экспорт.

### Кандидаты (`/candidates`)

Две вкладки:

- **«Растущие фразы»** — фразы, прошедшие выбранный пресет («Устойчивый рост»,
  «Ранние сигналы», «Рост от нуля»), отсортированные по приоритету исследования
  или по сглаженному приросту.
- **«Предложения групп»** — автоматические группы по повторяющимся значимым
  словам и парам соседних слов среди растущих фраз (минимум 5 разных фраз).
  Группа показывает примеры, размер, долю растущих, суммарную точную
  частотность состава и долю лидирующей фразы. Кнопка «Расширить» ищет по всему
  отчёту (включая нерастущие) — перед сохранением как нишу проверьте полный
  состав.

### Ниши (`/niches`)

Ниша — сохранённая подборка фраз с названием и описанием задачи. Два режима:

- **фиксированный список** — вы выбираете конкретные фразы;
- **правило поиска** — набор фильтров плюс ручные включения/исключения;
  пересчёт создаёт новую неизменяемую версию состава (старые оценки не
  переписываются).

Правило состава: `(совпадение с фильтрами ИЛИ ручное включение) И НЕ ручное
исключение`. Карточка ниши: состав, история, рост, концентрация на лидирующей
фразе, доля растущих участников, качество покрытия, связанные гипотезы;
кнопка «Экспорт CSV» выгружает состав и оценку текущей версии.
Общие фразы в двух нишах допустимы, но суммарный итог нескольких ниш считается
по объединению уникальных фраз.

### Гипотезы (`/hypotheses`)

Карточка гипотезы: название, связанная ниша, целевая аудитория, задача,
существующий способ решения, идея сервиса и минимальная полезная функция,
монетизация, подтверждающие фразы, следующий эксперимент и критерий результата,
статус («кандидат», «исследую», «проверяю», «в разработке», «отложено»,
«отклонено») и причина отклонения.

Аудитория, монетизация и конкуренция — ваши предположения, а не наблюдаемые
данные CSV; не выдавайте их за факты. В версии 1.0 внешний ИИ-агент (MCP)
карточки не изменяет — результаты исследования переносите через UI или API.

### Настройки (`/settings`)

Сведения о системе: версия приложения, версии правил метрик и профилей.

## Метрики: что они значат

Все метрики считаются на backend по точным частотностям `f1 … fn` (от старой к
новой) выбранного диапазона замеров (ТЗ §7).

### Базовые

| Метрика | Определение |
|---|---|
| Текущая частотность | `fn` — именно последнее значение, а не последний непустой |
| Абсолютное изменение | `fn − f1`, если обе границы известны |
| Относительное изменение | `(fn − f1) / f1`, если `f1 > 0`; при `f1 = 0` процент не определён — показывается «рост от нуля» |
| Изменение ранга | `rank_previous − rank_current`; предыдущий ранг `0` = «не было в прошлом рейтинге» |
| Низкая база | базовое значение ниже 20 (порог настраивается) |
| Широкая/точная | отношение широкого к точному в одном замере |

### Сглаженный рост и устойчивость (минимум 4 полных замера)

```text
B = (f1 + f2) / 2              — ранняя база
R = (f[n−1] + fn) / 2          — поздний уровень
A = R − B                      — сглаженный абсолютный прирост
G = (R − B) / B  (при B > 0)   — сглаженный относительный рост
C = доля переходов f[i] > f[i−1] — устойчивость
P = fn / max(f1 … fn)          — сохранение спроса относительно пика
```

При неполном ряде эти метрики не оцениваются по оставшимся точкам — приложение
возвращает пустое значение с причиной.

### Пресеты

| Пресет | Условия (все одновременно) | Сортировка |
|---|---|---|
| **Устойчивый рост** | ≥ 4 полных замера; `fn ≥ 100`; `B ≥ 20`; `A ≥ 50`; `G ≥ 0.30`; `C ≥ 0.60`; `P ≥ 0.70` | по приоритету |
| **Ранние сигналы** | ≥ 4 замера; `0 < B < 20`; `fn ≥ 50`; `A ≥ 30`; `G ≥ 1`; `C ≥ 0.60`; `P ≥ 0.70` | по `A` убыванием |
| **Рост от нуля** | ≥ 4 замера; `B = 0`; `fn ≥ 50`; `A ≥ 30`; `P ≥ 0.70` | по `A` убыванием |

Пороги — рабочие эвристики для первичного отбора, не статистически
валидированные границы перспективности. Результаты «Ранних сигналов» и «Роста
от нуля» не смешиваются с основным рейтингом: сигнал менее надёжен.

### Приоритет исследования (`priority_v1`)

```text
priority = round(100 × (0.30·g + 0.25·a + 0.20·C + 0.15·v + 0.10·T))
```

где `g`, `a`, `v` — нормированные с фиксированными масштабами рост, прирост и
объём, `T` — признак «задача для онлайн-сервиса» (сработавшее правило из
редактируемого словаря: «конвертер», «рассчитать», «из pdf в …» и т. п.).

Это **эвристический рейтинг для первичного отбора**, а не вероятность успеха и
не оценка прибыльности. Данных о конкуренции в формуле нет. Для низкой базы и
неполной истории приоритет пуст, с причиной.

## Правила интерпретации данных

Обязательные ограничения источника (ТЗ §4.1) — их нарушение ведёт к ложным выводам:

1. **Не складывайте широкие частотности** по фразам как объём рынка — они
   пересекаются. Сумма точных подписывается «суммарная точная частотность
   выбранных формулировок».
2. **Даты замеров неизвестны.** Ось истории порядковая; месячные и годовые
   темпы не считаются; замеры не называются месяцами.
3. **«Впервые в рейтинге» ≠ «впервые возникший спрос»** — фраза могла просто
   не попасть в прошлую выгрузку.
4. **Отсутствие строки, пустая ячейка (NULL) и ноль — три разных состояния.**
   Отсутствующая в отчёте фраза не считается нулём при агрегировании.
5. Изменение позиции в рейтинге — не то же, что изменение частотности.
6. История внутри текущего топа описывает только фразы из текущего отчёта, а не
   весь поисковый рынок.
7. Несколько близких замеров могут относиться к перекрывающимся периодам:
   устойчивость в них — описательная характеристика, а не доказательство
   независимости.

Пример из образца: «чемпионат мира матчи» — точная история
`1866, 846, 568, 468, 493, 14868825`. Огромный прирост сосредоточен в последнем
переходе, `C = 0.4` — фраза **не проходит** пресет устойчивого роста, хотя
относительный рост колоссален. Причины скачка (сезон, изменение данных) по
этому файлу установить нельзя.

## REST API и MCP

- **REST**: префикс `/api/v1`, JSON, без токенов (локальный loopback). Схема и
  список эндпоинтов: [openapi.yaml](openapi.yaml). Health-check:
  `curl localhost:8080/api/v1/health`.
- **MCP**: read-only сервер `niche-radar` (stdio, 12 инструментов + ресурс с
  методологией) для внешнего ИИ-агента. Конфигурация клиента:
  [mcp-client.example.json](mcp-client.example.json). Запуск:
  `docker compose exec -T app php artisan mcp:start niche-radar`.

## Частые вопросы

**Загрузил `Top10.csv`, а «Кандидаты» пустые. Это баг?**
Нет. Из 10 фраз образца ни одна не проходит пресет «Устойчивый рост» — это
контрольное значение (ТЗ §14.1). Предложения групп строятся по фразам, прошедшим
пресет, поэтому их тоже нет. Импортируйте полный отчёт (Top-100 и больше) для
реального отбора.

**Повторно импортировал тот же файл — данные задублировались?**
Нет. Одинаковый файл (совпадает SHA-256) возвращает существующий отчёт. Если
нужно обработать тот же файл с другими настройками разбора — оформите новую
ревизию обработки в интерфейсе загрузки.

**Почему по фразе нет процента роста, хотя частотность выросла?**
Базовая частотность была нулевой — процент от нуля не определён. Смотрите
абсолютное изменение и подпись «рост от нуля».

**Порт 8080 занят.**
Укажите `APP_PORT=8180` (или `127.0.0.1:8180`) в `.env` и выполните `make restart`.

**Как сравнить два отчёта?**
Через REST или MCP: `POST /api/v1/analytics/compare`, явно указав базовый и
текущий отчёт. Сравниваются текущие замеры, рост суммы
считается на пересечении фраз со значениями в обоих отчётах; вошедшие и
